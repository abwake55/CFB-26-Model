# Leak fix and re-baseline — November 24, 2026

## What was wrong

1. **Same-season SP+ (main leak).** `situational._load_ratings` keyed SP+ by
   `(year, team)` using the season-final rating. Lookahead and sandwich features
   for a September game therefore knew how good both teams ended the season.
   Fixed: ratings are now keyed `(year + 1, team)`, so a season only sees the
   PRIOR season's final SP+. `tests/test_leakage.py` pins this.
2. **Closing line as a feature.** `spread_magnitude` (|closing spread|) was an
   input to models whose target is margin minus the closing spread. Removed.
3. **Observed game-day weather.** Totals used observed wind/temperature/precip.
   There is no archived pre-kickoff forecast for the training years, so these
   were dropped from training (`is_dome` kept). Live forecast weather still
   feeds the CORE wind gate.
4. LightGBM capacity cut from `num_leaves` 63 to 7 (`min_child_samples` 60,
   `reg_lambda` 5). It had the best out-of-sample MAE of 63 / 15 / 7.

them as research, not proof of an edge.

## In-season ratings (research, not default)

`src/inseason_ratings.py` builds point-in-time PPA and margin ratings using
only games on earlier dates, shrunk toward the prior-season fit. Their
correlation with the closing margin in weeks 8+ is 0.946, vs 0.681 for
prior-season SP+. Adding them moved spread edge>=3 to 53.2% (+1.5% ROI) and
CORE to 57.0%, but MAE got slightly worse (spread 12.379, totals 12.766). They
stay off by default. Reproduce with `python scripts/experiment_walk_forward.py
NAME --inseason`.
